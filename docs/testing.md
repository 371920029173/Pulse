# 测试与检查

```bash
pnpm check:offline   # 不需要 API key 的全部内容 —— 也是 CI 跑的那条
pnpm check:all       # 上面这些 + 自我验证评测（调模型，需要 key）
```

`check:all` 只是 `check:offline && eval:verify`，所以两条链不会漂移。

单测：`pnpm -r test`（6 个包，990 项）。除 `eval:agent` / `eval:verify` 外**全部离线、不花钱**。

两个评测的判分都是**确定性断言**（文件系统、命令输出、回复字符串），不调用 LLM 判分 ——
那会让成本翻倍并引入不确定性。它们按**通过率**判定而不是要求满分，因为测的是模型行为：
随机变红的门禁等于没有门禁。

## 每个检查守什么

这里**故意不写每项的断言数量**。那种数字每加一条断言就过期，而一个过期的数字比没有数字更糟
—— 读者会以为它在被维护。（`check:docs` 会校验文档里引用的**总数**是真实的，方法是真的去跑
一遍测试；但每个检查的细分数它管不了，所以文档也不声称。）

| 检查 | 守什么 |
|---|---|
| `check:data` | 状态文件损坏时**留底而不是清空**，旧版本就地升级不丢内容 |
| `check:restart` | 硬杀进程再重启：设置、会话、讨论群、定时任务、样式都还在；损坏的文件被 `.unusable-` 留底 |
| `check:encoding` | 中文/emoji 在接口、落盘、重启后都完好；`charset=utf-8` 声明与实体一致 |
| `check:security` | 跨站请求、伪造 Host、工作区越界、符号链接逃逸都被拒 |
| `check:host` | 绑定地址 / 允许域名 / DNS rebinding 防护（回环名、字面 IP、显式域名、通配符） |
| `check:shell` | Shell 引号正确性；命令白名单是 **fail-closed**，且每段链式命令都被检查 |
| `check:lock` | 会话级轮次锁：并发请求得 **409** 而不是互相污染 |
| `check:subagent` | 子智能体拿不到 `task_spawn`（防递归）与需要人在场的工具 |
| `check:preflight` | 开工前预检：不存在的 `@file:`、越界路径、无排程工具却要「提醒」都被挡下；声称的置信度被压到检查结果允许的上限；旧计划不被当成续做指令 |
| `check:toolresult` | 工具返回值统一校验：非零退出码/空结果/失败原因分类；驱动真实工具与真实 Agent，并检查源码里每条 `Error:` 文案都有对应去路 |
| `check:errorbook` | 错题本：真实失败写进 KB 的 `errors/<tool>`，重复失败合并计数；查「过去踩过的坑」只返回错题本内的条目，混不进普通知识 |
| `check:plan` | 计划是**依赖图**不是清单：前置没完成时不能开始/不能标完成；`skip` 级联跳过、`stop` 停在 `[!]`、`retry` 记次数、`ask` 指明问用户；换 store / 换会话后仍按「下一步」续做 |
| `check:delivery` | 交付模板：结论/证据/假设/风险/待确认，**证据是必填**；`done` 在还有待确认项、或本会话计划还没做完时被拒（并点名那些步骤）；简版/详版；`kind=report` 不受影响 |
| `check:audit` | 审计日志**只增不改**（已有字节是原文前缀）、`seq` 跨重启与轮转严格递增、轮转丢弃被记录、损坏行被计数并报给接口；伪造的 `ticket_id` 不会变成"人工已批准"；`/api/audit` 只读且过滤参数严格 |
| `check:runs` | 运行轨迹：一轮一个文件、文件名严格递增（同毫秒、时钟回拨都不会把最新的排到后面）、失败/停在等人工/被中断三种结局分得清、**凭据不落盘**（含嵌套与工单）、截断记录原文长度、半行被计为损坏；`corroborate` 能挡下"点名了没跑过的工具"的编造证据；`/api/runs` 只读且路由顺序正确 |
| `check:reflection` | 自省：漂移检测只在有证据时开口（硬约束越界才算漂移、软约束只提醒、模糊偏好不误报）；置信度镜像的样本来自预检自评 × 本轮真实工具成功率（没有自评不产生样本、没有工具调用的轮次不进成功率），样本不足不下结论、损坏文件当空历史、跨进程可读；反思写成**教训**落进 `errors/自省` 并查得回来、同主题复发加计数；独立批评者只有"说法与轨迹矛盾"才判不通过，说不出所以然的说法不进结论；`/api/reflection` 在新进程里也能读到盘上的历史，重置留 `config` 审计 |
| `check:budget` | 预算开关、只读并发与同轮复用：**关着的时候行为逐字节不变**（跑到最后、每次调用都真跑）；打开后三条轴（轮数/调用次数+时间/Token）各自在真实 Agent 上生效，消息中途被拦下的调用补 `not_run` 让下一轮还能接着追加，停止文案说明上限、已用量、能说「继续」，且**不是任务失败**；只读工具只预取开头连续的一段（写之后的读留给串行路径、没见过的工具名默认串行），并发上限为 `MAX_PARALLEL_READS`；同轮里同样的只读查询只碰一次文件系统、复用结果与首次逐字节相同、**任何写就让缓存失效**、缓存不跨轮 |
| `check:reflection` | 自省：漂移检测只在有证据时开口（硬约束越界才算漂移、软约束只提醒、模糊偏好不误报）；置信度镜像的样本来自预检自评 × 本轮真实工具成功率（没有自评不产生样本、没有工具调用的轮次不进成功率），样本不足不下结论、损坏文件当空历史、跨进程可读；反思写成**教训**落进 `errors/自省` 并查得回来、同主题复发加计数；独立批评者只有"说法与轨迹矛盾"才判不通过，说不出所以然的说法不进结论；`/api/reflection` 在新进程里也能读到盘上的历史，重置留 `config` 审计 |
| `check:theme` | 自定义样式：锁死拦截、两条逃生通道、只读文件/目录/异常字节、换工作区不换肤 |
| `check:uistruct` | 结构不变量：根级状态没被挂进面板、浮层两个分支都渲染、注入不走 `innerHTML` |
| `check:api` | UI 调用的每个接口在服务端都有路由（**按方法匹配**）—— 防"半个功能" |
| `check:plugins` | 插件**端到端**：安装 → 智能体真能调 → 返回真实数据 → 卸载不重启即失效 |
| `check:dist` | 构建产物：无第三方字体/样式引用，关键接线确实在产物里 |
| `check:logs` | 日志有上限；`crash.log` 只装崩溃，不装例行警告 |
| `check:a11y` | 可聚焦、可键盘关闭、图标按钮有名称 |
| `check:portability` | 平台专有调用是否都有分支；没有硬编码盘符路径 |
| `check:metrics` | 指标端点结构与初始状态 |
| `check:schedule` | 定时任务：窗口外**顺延而非丢弃**，到点不中断在跑的活 |
| `check:lsp` | 语言服务器接线与正确性（含冷启动预热、内容变更后诊断更新） |
| `check:i18n` | 本地化覆盖率**棘轮**：不允许新增硬编码文案 |
| `check:ui` | 控件样式一致性：填充、hover、高度、死 CSS |
| `check:docs` | 文档：引用的文件存在、引用的总数真实、没有留下未完成的标记、每个检查脚本都被文档提到 |
| `check:docker` | 容器镜像结构（COPY 路径、非 root、健康检查）—— 无 docker 时的静态核对 |
| `check:release` | 发布包头结构 |
| `check:packaged` | **打包产物能启动**：跑解包后的服务端并探活，且界面是最新那份 |

## 安装包验证

```bash
pnpm release          # 跑门禁 → 构建 → 打包到 release/
pnpm release:verify   # 解压归档、真正 pnpm install、启动并探活
pnpm pack:win         # 打 Windows 安装包；结尾自动跑 check:packaged
```

> `pack:win` 结尾会跑 `check:packaged`，所以**一个装完起不来的安装包不可能被打出来**。
> 这条规则是有来历的：打包用的 `pnpm deploy` 默认是虚拟存储结构，某个包的依赖写在它的**同级
> 目录**，而旧打包脚本把符号链接展平成实体目录后，那些依赖就找不到了。当时 `@she/shared`
> 还没有运行时依赖，所以问题潜伏到新增一个（`yaml`）才暴露 —— 安装包启动即报
> `ERR_MODULE_NOT_FOUND`，而且没人真正启动过安装包。

## 已知的测试缺口

诚实记录，这些是**没被证明**的部分：

- **Windows 11 / macOS 从未运行过。** `check:portability` 静态审计了所有源文件里含平台分支的，
  也验证了启动器与进程终止的分平台处理，但那些平台上一个进程都没起过。
- **容器镜像未构建过。** 本机没有 docker；`check:docker` 只核对结构，不等于 `docker build` 能过。
- **无障碍只做了静态部分。** 可聚焦性、键盘关闭、按钮名称已检查；颜色对比度、屏幕阅读器实读、
  焦点顺序、缩放未验证。
- **界面本地化未完成**：622 处中文文案仍硬编码（棘轮基线见 `scripts/i18n-baseline.json`）。基础设施已就位（`t()` 以中文原文为 key，
  缺翻译时显示中文而非裸 key），并有棘轮防止倒退。
- **评测规模偏小**：检索 16 例、Agent 10 例、自我验证 5 例，且只用了一个模型。
- **没有 embedding 对比基线**：当前 provider 无 `/embeddings` 端点（实测 404），
  所以只能说"优于纯 BM25"。评测会明确报告这一点，而不是省掉那一列。
- **长程任务（>10 轮）仍未覆盖。**
- **计分只在单次运行上做过**：没有多次运行取方差，所以通过率的波动范围未知。
