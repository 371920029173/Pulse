# 测试与检查

```bash
pnpm check:offline   # 不需要 API key 的全部内容 —— 也是 CI 跑的那条
pnpm check:all       # 上面这些 + 自我验证评测（调模型，需要 key）
```

`check:all` 只是 `check:offline && eval:verify`，所以两条链不会漂移。

单测：`pnpm -r test`（6 个包，1317 项）。除 `eval:agent` / `eval:verify` 外**全部离线、不花钱**。

两个评测的判分都是**确定性断言**（文件系统、命令输出、回复字符串、以及「这次跑了哪些工具」），不调用 LLM 判分 ——
那会让成本翻倍并引入不确定性。它们按**通过率**判定而不是要求满分，因为测的是模型行为：
随机变红的门禁等于没有门禁。

但通过率有个天生的盲区：**一次采样分不清「回归」和「波动」**。所以两个评测都能
`--repeat N`（默认 1，API 花费约 N 倍），报告每个任务的通过次数与用量方差，并给出结论：

- **回归** —— N 次全挂（N ≥ 3）：一定是坏了，门禁直接红，哪怕平均通过率还高于门槛
  （平均值会盖掉一个死掉的工具）；
- **波动** —— 有时过有时不过：是判据不稳，报出来但不拦发布；
- 只跑 1 遍时只报「不确定」，并按老规则用通过率判定，行为与以前逐字节相同。

`evals/agent` 里另有一组 `long-horizon-*` 任务（5～6 轮）：一个编号要在隔了 4 轮无关工作之后
还能被想起来、一个文件要在 5 轮里持续累加、一个产物要在 5 轮反复修改后仍然齐全。它们都带
`turnPromptGrowth` 判据 —— 长程运行真正的死法不是某一轮出错，而是上下文一轮比一轮大，最后
又慢又贵到超时。任务定义本身可以在**不花钱、不需要 key** 的前提下先校验：`node evals/agent/run.mjs --dry-run`。

有两条任务判的是**路径**而不是结果，因为结果判不出它们要测的东西：

- `greeting-cheap`：「你好」一次工具都不能调（`toolCallsAtMost: 0`）。在这之前它只有一条
  `usageBelow` 用量上限当代理指标，而代理指标会漂：系统提示词加工具表的固定开销实测约 11k
  prompt tokens（三次跑 sd 个位数），早就越过了当初按更小的提示词定的 8000，于是任务恒红而
  行为其实是对的。上限改成按实测值定的天花板（只抓爆发式增长），意图改由工具调用数直接断言。
- `subagent-delegation`：必须真的调用 `task_spawn`（`toolCallsInclude`）。这条任务以前只断言
  `answer.txt` 的内容，于是父智能体自己 `fs_list`+`grep` 把答案找出来也照样通过 —— 而那时这个
  harness 根本没给 Agent 注入 `subagentRunner`，`task_spawn` 压根不在工具表里，所谓「委派」从来
  没被跑过。现在 harness 会注入一个 runner（生产里服务端也是这么装配的），这条任务才真的在测委派。
- `kb-proactive-recall` / `kb-no-raw-sqlite`：答不出来才叫考检索。任务通过 `kb` 字段先把记忆种进
  库里，工作区里**没有任何文件**提到答案 —— 所以不主动 `kb_query` 就不可能答对（判据同时要求
  「查了」和「答对了」：只判答复能靠猜蒙对，只判调用则调了不用等于白调）。第二条再用
  `toolCallsExclude` 把 `shell` / `fs_read` / `fs_write` 全部钉死：真实运行里出现过
  `sqlite3 .she/kb.sqlite "SELECT ..."`，绕过共振排序与访问计数，还在服务端已经打开的库上多抓了
  一个句柄。工具层现在也会在确认门之前直接拒绝这种直连（见 `KB_DIRECT_ACCESS_REASON`），
  这条任务保证模型不会退化成「先试直连、被拒了再查」——被拒也是一次调用。

harness 为了让 `task_spawn` 存在而注入的 runner 把子智能体放在**同一个临时工作区**里跑：临时
目录不是 git 仓库，副本隔离在评测里永远是「未隔离」。工作副本的建/用/收口由离线 `check:isolation`
断言（不需要花钱），评测只负责证明「派出去、拿回结果」这条路通。

## 每个检查守什么

这里**故意不写每项的断言数量**。那种数字每加一条断言就过期，而一个过期的数字比没有数字更糟
—— 读者会以为它在被维护。（`check:docs` 会校验文档里引用的**总数**是真实的，方法是真的去跑
一遍测试；但每个检查的细分数它管不了，所以文档也不声称。）

| 检查 | 守什么 |
|---|---|
| `check:data` | 状态文件损坏时**留底而不是清空**，旧版本就地升级不丢内容 |
| `check:restart` | 硬杀进程再重启：设置、会话、讨论群、定时任务、样式都还在；损坏的文件被 `.unusable-` 留底 |
| `check:encoding` | 中文/emoji 在接口、落盘、重启后都完好；`charset=utf-8` 声明与实体一致；**仓库自己的文本文件都是合法 UTF-8** |
| `check:security` | 跨站请求、伪造 Host、工作区越界、符号链接逃逸都被拒 |
| `check:host` | 绑定地址 / 允许域名 / DNS rebinding 防护（回环名、字面 IP、显式域名、通配符） |
| `check:shell` | Shell 引号正确性；命令白名单是 **fail-closed**，且每段链式命令都被检查 |
| `check:lock` | 会话级轮次锁：并发请求得 **409** 而不是互相污染 |
| `check:subagent` | 子智能体拿不到 `task_spawn`（防递归）与需要人在场的工具 |
| `check:preflight` | 开工前预检：不存在的 `@file:`、越界路径、无排程工具却要「提醒」都被挡下；声称的置信度被压到检查结果允许的上限；旧计划不被当成续做指令 |
| `check:toolresult` | 工具返回值统一校验：非零退出码/空结果/失败原因分类；驱动真实工具与真实 Agent，并检查源码里每条 `Error:` 文案都有对应去路 |
| `check:errorbook` | 错题本：真实失败写进 KB 的 `errors/<tool>`，重复失败合并计数；查「过去踩过的坑」只返回错题本内的条目，混不进普通知识；**踩错的东西能退役**（`errorbook_forget` 记下理由，查询与预检都不再带上它），**同样的失败再来一次自己回来**而不是被永久静音；退役后该写入的仍然写，退役只影响读取 |
| `check:plan` | 计划是**依赖图**不是清单：前置没完成时不能开始/不能标完成；`skip` 级联跳过、`stop` 停在 `[!]`、`retry` 记次数、`ask` 指明问用户；换 store / 换会话后仍按「下一步」续做 |
| `check:delivery` | 交付模板：结论/证据/假设/风险/待确认，**证据是必填**；`done` 在还有待确认项、或本会话计划还没做完时被拒（并点名那些步骤）；简版/详版；`kind=report` 不受影响 |
| `check:audit` | 审计日志**只增不改**（已有字节是原文前缀）、`seq` 跨重启与轮转严格递增、轮转丢弃被记录、损坏行被计数并报给接口；伪造的 `ticket_id` 不会变成"人工已批准"；`/api/audit` 只读且过滤参数严格 |
| `check:runs` | 运行轨迹：一轮一个文件、文件名严格递增（同毫秒、时钟回拨都不会把最新的排到后面）、失败/停在等人工/被中断三种结局分得清、**凭据不落盘**（含嵌套与工单）、截断记录原文长度、半行被计为损坏；`corroborate` 能挡下"点名了没跑过的工具"的编造证据；`/api/runs` 只读且路由顺序正确 |
| `check:reflection` | 自省：漂移检测只在有证据时开口（硬约束越界才算漂移、软约束只提醒、模糊偏好不误报）；置信度镜像的样本来自预检自评 × 本轮真实工具成功率（没有自评不产生样本、没有工具调用的轮次不进成功率），样本不足不下结论、损坏文件当空历史、跨进程可读；反思写成**教训**落进 `errors/自省` 并查得回来、同主题复发加计数；独立批评者只有"说法与轨迹矛盾"才判不通过，说不出所以然的说法不进结论；`/api/reflection` 在新进程里也能读到盘上的历史，重置留 `config` 审计 |
| `check:budget` | 预算开关、只读并发与同轮复用：**关着的时候行为逐字节不变**（跑到最后、每次调用都真跑）；打开后三条轴（轮数/调用次数+时间/Token）各自在真实 Agent 上生效，消息中途被拦下的调用补 `not_run` 让下一轮还能接着追加，停止文案说明上限、已用量、能说「继续」，且**不是任务失败**；只读工具只预取开头连续的一段（写之后的读留给串行路径、没见过的工具名默认串行），并发上限为 `MAX_PARALLEL_READS`；同轮里同样的只读查询只碰一次文件系统、复用结果与首次逐字节相同、**任何写就让缓存失效**、缓存不跨轮 |
| `check:cost` | 回显瘦身**不省信息**：`plan_update` 只印本次动过的步骤备注（其余步骤**状态照印**，备注仍可由 `plan_list` 全量读出，盘上存的是原文），实测 12 次更新从 10779 字符降到 4242（−61%）；`kb_query` 默认把长正文摘要到开头并**明说截断 + 给出 `full=true` 的取回路径**，短记忆（约定/端口/命令）**原样完整返回**，节点标题与 id 一个不藏，`full=true` 逐字还原原文（实测默认 2363 ↔ 全文 10432，−77%）。省的是重复，不是信息 |
| `check:guardrail` | 出口合规护栏：该抓的抓到（私钥块/厂商前缀/JWT/Bearer/带密码连接串/凭据赋值）、**不该抓的不抓**（git hash、UUID、带端口的普通 URL、`sk-learn` 这种词、句中的 confidential、18 位纯数字）；回答**只报告不改写**（说的和记的必须对得上）；交付文件**拦下来**（`acknowledge_sensitive` 可覆盖）；落盘的第二份拷贝（轨迹 + 审计）把值洗掉而留下隐去标记 |
| `check:config` | 配置 last-good 回退：好配置写快照、坏配置用它启动并报 `degraded`、**坏文件一个字不动**、快照不被坏内容覆盖、没有安全网时仍然大声失败；`POST /api/config/rollback` 把快照放回去且留底，并进 `config` 审计 |
| `check:isolation` | 子任务隔离：只有声明了 `scope` 的写任务才开 git worktree（只读任务留在共享 checkout，否则看到的是上一次提交而不是当前改动）；副本**带走父级未提交的改动**；子级被关在副本里、父级工作区**始终干净**；会改文件却不写交付物在派发前就被拒；隔离建不起来时**明说**而不是静默降级；副本名支持中文；同名任务各自一个副本；隔离出来的会话在列表里看得见。**子任务的知识库**（与隔离是两件事）：每个子级都拿到父级库的**私有副本**（放在应用目录而不是副本目录里 —— 库是脚手架不是产出），副本里查得到父级已知的东西、也写得进去；结束时**回读它新建的节点交给父级**（回执里给标题和开头，全文另存一份摘要文件），**副本随后删除**，父级库本身一条不动 —— 收割是读取，不是替父级决定；删完之后副本目录能被删掉（服务端没有把库句柄一直攥着） |
| `check:tenant` | 鉴权与租户边界：默认关闭；开启是 fail-closed（token 太短/两个租户撞车 → 启动即抛错）；token 只从请求头读（查询串不算）、比较常数时间、**哪个地方都不回显**；`/api/health` 免鉴权而配置回退视图不免；跨租户拿 id 直取得 404、列表与 `/api/conversations` 都过滤；被拒绝的请求进 `auth` 审计且不写 token；无主会话在单租户下可读、多租户下拒绝 |
| `check:evals` | 评测框架自己：重跑才分得出**回归**（N 次全挂，N≥3）与**波动**（时过时不过）；平均值盖不住一个死掉的工具；波动不拦发布；只跑 1 遍时行为与老版本逐字节相同；任务定义错了（判据名写错、夹具不是字符串、长程任务只有 2 轮）在花钱之前就被挡住；`toolCallsAtMost` 的 `max: 0`（"一次工具都不许调用"）是合法值而不是被判成缺参数；`--dry-run` 在没有 key、端点不可达的机器上也能跑通；**两条按名称钉住的意图断言**（问候语必须 `toolCallsAtMost: 0`、委派必须 `toolCallsInclude: task_spawn`）不能被悄悄删掉 |
| `check:theme` | 自定义样式：锁死拦截、两条逃生通道、只读文件/目录/异常字节、换工作区不换肤 |
| `check:uistruct` | 结构不变量：根级状态没被挂进面板、浮层两个分支都渲染、注入不走 `innerHTML` |
| `check:api` | UI 调用的每个接口在服务端都有路由（**按方法匹配**）—— 防"半个功能" |
| `check:plugins` | 插件**端到端**：安装 → 智能体真能调 → 返回真实数据 → 卸载不重启即失效 |
| `check:mcp` | MCP 工具**端到端**（起真服务 + 桩模型 + 真子进程 server）：**开机就把 server 的工具注册给 agent**（探测数 = 注入数 —— 防住「面板说 14 个、agent 一个没有」那种不报错的静默失败，这个病已经犯过两次）；`mcp_*` 真的出现在模型工具表里、调用走 `tools/call` 并把子进程的原话带回来；停用/启用**不重启**即生效（工具表被重建，面板与 agent 说的一致）；server 报 `isError` 是失败而不是静默成功；检查自带隔离（把自己的 HOME/APPDATA 指到临时目录），所以读不到本机 Cursor 配置，CI 与本机看到的是同一份清单 |
| `check:dist` | 构建产物：无第三方字体/样式引用，关键接线确实在产物里 |
| `check:logs` | 日志有上限；`crash.log` 只装崩溃，不装例行警告 |
| `check:a11y` | 可聚焦、可键盘关闭、图标按钮有名称；**颜色对比度按 token 实测**（两个主题 × 每个文字色 × 每个表面色，正文 4.5:1 / 着色表面 3:1），填充控件上的文字必须用 `--on-*`（白字在浅色主色上只有 2.6:1）；焦点环必须写在 `:focus{outline:none}` 之后；没有正数 `tabIndex` |
| `check:portability` | 平台专有调用是否都有分支；没有硬编码盘符路径 |
| `check:wsl` | POSIX 文件在工作副本里是 **LF**（`git status` 看不出来：`eol=lf` 会先把工作副本换算成 LF 再比对，而 shell 执行的是工作副本）；`*.sh` 在 git 索引里**可执行**（在 Windows 上它不是文件属性，chmod 无效，所以只能查索引）；shebang 可移植。WSL 里若有 Node ≥ 20，会把零依赖的检查真的在 Linux 上跑一遍，否则**报阻塞并给出修复命令**，而不是静默跳过 |
| `check:metrics` | 指标端点结构与初始状态 |
| `check:schedule` | 定时任务：窗口外**顺延而非丢弃**，到点不中断在跑的活 |
| `check:lsp` | 语言服务器接线与正确性（含冷启动预热、内容变更后诊断更新） |
| `check:i18n` | 本地化覆盖率**棘轮**：不允许新增硬编码文案 |
| `check:ui` | 控件样式一致性：填充、hover、高度、死 CSS |
| `check:docs` | 文档：引用的文件存在、引用的总数真实、没有留下未完成的标记、每个检查脚本都被文档提到 |
| `check:docker` | 容器镜像结构（COPY 路径、非 root、健康检查）—— 无 docker 时的静态核对 |
| `check:release` | 发布包头结构 |
| `check:packaged` | **打包产物能启动**：跑解包后的服务端并探活，且界面是最新那份 |

## 安装包验证

```bash
pnpm release          # 跑门禁 → 构建 → 打包到 release/
pnpm release:verify   # 解压归档、真正 pnpm install、启动并探活
pnpm pack:win         # 打 Windows 安装包；结尾自动跑 check:packaged
```

> `pack:win` 结尾会跑 `check:packaged`，所以**一个装完起不来的安装包不可能被打出来**。
> 这条规则是有来历的：打包用的 `pnpm deploy` 默认是虚拟存储结构，某个包的依赖写在它的**同级
> 目录**，而旧打包脚本把符号链接展平成实体目录后，那些依赖就找不到了。当时 `@she/shared`
> 还没有运行时依赖，所以问题潜伏到新增一个（`yaml`）才暴露 —— 安装包启动即报
> `ERR_MODULE_NOT_FOUND`，而且没人真正启动过安装包。

## 已知的测试缺口

诚实记录，这些是**没被证明**的部分：

- **Windows 11 / macOS 从未运行过。** 本机是 Windows 10（19045）。`check:portability` 静态审计了
  所有源文件里含平台分支的，也验证了启动器与进程终止的分平台处理，但那些平台上一个进程都没起过。
- **Linux 上的真实运行是阻塞的，不是通过的。** `check:wsl` 会去找 WSL：本机能连到 Ubuntu
  （内核 6.18 WSL2），但里面**没有 Node**，所以那几条零依赖检查没跑成，报告里明确写着「阻塞」。
  装完 Node 之后同一条命令会自动开始跑。另外即使跑起来也**不等于**完整验证：工作区挂在
  `/mnt/d`（drvfs，默认大小写不敏感），所以在那里跑不出「路径大小写」这类 Linux 专有问题。
- **容器镜像未构建过。** 本机没有 docker；`check:docker` 只核对结构，不等于 `docker build` 能过。
- **无障碍只做了静态部分。** 可聚焦性、键盘关闭、按钮名称、颜色对比度（按 token 实测）、焦点环
  顺序已检查；但**屏幕阅读器实读、焦点陷阱是否真的生效、200% 缩放下的重排**未验证 ——
  半透明色块和图片背景上的文字也算不出来，因为合成结果取决于未知的祖先表面。
- **界面本地化未完成**：仍有中文文案硬编码（棘轮基线见 `scripts/i18n-baseline.json`）。
  基础设施已就位（`t()` 以中文原文为 key，缺翻译时显示中文而非裸 key），并有棘轮防止倒退。
- **评测规模偏小**：检索 16 例、Agent 13 例、自我验证 5 例，且只用了一个模型。
- **评测里的子任务不开副本**：`evals/agent` 的临时工作区不是 git 仓库，注入的 runner 把子智能体
  放在共享目录里跑，所以「派出去、拿回结果」这条链有真实覆盖，「子任务在私有副本里改文件」没有
  —— 那部分由离线 `check:isolation` 断言，不需要花 API 钱。
- **没有 embedding 对比基线**：当前 provider 无 `/embeddings` 端点（实测 404），
  所以只能说"优于纯 BM25"。评测会明确报告这一点，而不是省掉那一列。
- **长程只覆盖到 6 轮。** `long-horizon-*` 三个任务跑 5～6 轮并检查上下文是否逐轮膨胀，
  但 >10 轮、以及跨会话续做的长程仍未覆盖。
- **方差只在 N ≥ 2 时有意义**：`--repeat` 会报通过次数与用量方差，默认仍只跑 1 遍，
  这时脚本明说「不确定」而不是给一个看起来像结论的数字。
