# 2.0：从「模型自愿查记忆」改成「系统默认推送」

> 起因：用户的观察——模型**不知道自己不知道什么**，于是不回查 KB；地图也很少用；上下文机制粗糙。
> 参考外部资料 `aaa.md`（召回分层 L0–L4 + 锚点类型学），按本仓库的硬约束做了取舍。

## 一、外部资料里哪些直接可用，哪些不能照抄

| 资料主张 | 我们的取舍 | 原因 |
|---|---|---|
| 召回从「tool call」降级为流水线默认动作 | **采纳**（这就是 2.0 的主线） | 工具描述再详细也解决不了 unknown unknowns |
| L0 常驻记忆卡（300–1500 token，确定性注入） | **采纳，但压到 ≤400 token** | 前缀缓存按字节算，卡片必须稳定 |
| L1 每轮自动召回，注入在**决策点附近** | **采纳**（已有 `withAutoRecall`，改造而非新建） | 已有实现只注入"检索结果"，缺"为什么召回"和"不够就补查" |
| 混合检索（向量 + BM25 + rerank） | **不采纳** | 仓库规则：禁止 embedding / vector RAG。检索仍是 PulseSeed 结构共振 + 词法入口 |
| 结构化记忆走 SQL/图查询，语义只兜底 | **采纳**：组过滤 + 边扩散已有，补"条件锚" | 这就是我们比向量方案强的地方 |
| 锚点 = 匹配器，不是路径（六类） | **采纳**，新增 `recall_when` | 逼模型编文件锚点只会污染检索 |
| 写入侧记忆整合（去重/冲突消解/时效） | **部分采纳**：已有 kb_edit/kb_retire，缺"生效/失效时间" | 不做会新旧冲突 |
| 事后 critic 复核漏召回 | **采纳（第 3 阶段）** | 先有评测集，否则 critic 没法定阈值 |
| balanced 正负评测集 + 按锚点类型分桶 | **采纳，且是 2.0 的验收标准** | 单看召回率一定会被调成过度检索 |

## 二、我们缺的到底是什么（现状对照）

| 层 | 现状 | 缺口 |
|---|---|---|
**L0 常驻** | 无。系统提示词里只有工具说明 | 模型不知道"库里有什么领域"→ 直接答，不查 |
**L1 每轮召回** | 有 `withAutoRecall`（按当前消息做一次结构共振） | 没有组过滤、没有"为什么相关"、没有预算分级 |
**L2 路由** | 无。每轮同一套检索 | 读代码的轮次和闲聊的轮次被同样对待 |
**L3 工具** | 有 `kb_*` 全套 | 描述没写 when/when-not；参数多；结果没有稳定 ID 语境 |
**L4 校验** | 无 | 漏召回没有任何信号 |
**写入侧** | `kb_upsert` 有组/边/去重 | 没有 `recall_when`（何时该被想起） |
**地图** | 有 `map_*` + 每轮末尾一小段摘要 | 改文件前不会自动出现"影响面"，所以"想到才用" |
**上下文** | 压缩在错误窗口下触发（128k 猜 1M）；摘要固定 8k 字符；`covered` 冻结 | 压缩吃掉历史（AGI 会话 39,056 条 → 一份摘要） |

## 三、2.0 的八步（每步独立可回滚）

1. **知识目录卡（L0）**：每轮注入 ≤400 token 的"库里有什么"——组名、条数、最近写入时间。放系统消息**尾部**并随会话冻结（不破坏前缀缓存）。判据：卡片在 10 轮内逐字节不变。
2. **`recall_when`（写入侧）**：`kb_upsert` 增加必填"未来什么上下文该召回它"；写不出 → 降级为待确认。旧节点允许空，检索时降权（不删）。
3. **条件锚路由（L2）**：纯规则，不调模型。按任务类型（改代码/查历史/写文档/闲聊）× 提及实体，决定检索计划：查哪些组、几跳、预算多少。
4. **决策点的召回状态行**：每轮末尾一行——「已自动召回 3 条（id: …），其中 2 条强锚；不够就 `kb_query`」。把提醒搬到决策点旁边。
5. **地图从"调用"变"推送"**：准备改某个文件时，自动附一行 `map_impact` 摘要（谁引用、要跑哪些 check）。判据：改文件的那一轮，摘要出现在请求里。
6. **上下文 2.0**：窗口三来源（`SHE_CONTEXT_WINDOW` / `llm.contextWindow` / 模型名）并**在接口里点名**；摘要按比例（原文 5%，上限 6 万字符）；`covered` 随压缩递进；压缩前把原文留在 `compacted/`（已能重建）。
7. **评测（验收标准）**：balanced 正负集（记忆依赖 / 明显不依赖各半）+ 分桶指标（强锚 recall、弱锚 precision、L0 采纳次数）+ 门禁 `check:recall`。
8. **文档与迁移**：`docs/context-and-caching.md` 重写相关章节；手册加"为什么它现在会自己想起来"；旧库迁移说明。

## 四、不做什么（写清楚，防止 2.0 跑偏）

- **不做向量库**（仓库规则）；召回精度靠组结构、边扩散、条件锚，而不是相似度。
- **不做"每轮都全量召回"**：预算硬上限，超时降级为只给 L0。
- **不把摘要当成历史**：压缩必须保留原文可回溯（`compacted/` 是证据链）。
- **不靠调 prompt 提升工具使用率**：改默认路径，不改措辞。这一条是外部资料里最值钱的一句。

## 五、一句话

> 让"查记忆"从模型的自由意志变成系统的默认路径；模型只负责在默认路径不够用时补刀。
