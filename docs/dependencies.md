# 依赖：谁是过期的、为什么不升

`pnpm outdated` 是这份文档的唯一来源：**每一条列出来的都要有决定**（升，或者写下不升的理由）。
它不是门禁 —— 门禁是 `check:deps`（依赖**告警**棘轮，见 `docs/testing.md`），那管的是安全告警，
这里管的是版本是否落后。两者互补：告警是事后告知，这份表是"看一眼就知道有没有人管"。

## 2026-10-11 的决定

| 包 | 当前 | 最新 | 决定 |
|---|---|---|---|
| `typescript-language-server`（dev） | 6.0.1 | 6.0.2 | **升到 6.0.2**。补丁版本，升完 `pnpm check:lsp` 全部通过（LSP 通道的越界拒绝、链接处理那几条判据都还在）。 |
| `@types/node`（dev） | 22.20.5 | 26.6.5 | **保持 22.x**。类型要跟**运行时**对齐：本机与 CI 跑的都是 Node 22（`node -v` = v22.16.0）。升到 26 等于让类型描述一个当前跑不到的运行时——能编译，但写出来的 API 运行时不存在。要升它，先升运行时。 |
| `@types/react` | 18.x | —— | **不在过期列表里**（已与仓库用的 React 18 对齐）。同一条规则：类型跟框架版本走，不追最新。 |

规则一句话：**devDependencies 追补丁、运行时相关的类型跟运行时**；每一次升都要有判据跑过（LSP / 构建 / 套件），
不是"看到有新版本就升"。
