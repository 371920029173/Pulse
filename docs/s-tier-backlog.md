# SHE 能力任务清单（已确认）

对照桌面 `a.txt`。必须项和加分项都在这份清单里。每一大条写三件事：要做到什么、现有实现对得上哪、还要补什么。

状态：已有 / 部分 / 未做。

不做的只有这几件，其余加分项都改写成 SHE 做得到的任务，不整段删掉。每条都写清理由，避免下次再拿出来重新讨论一遍：

- **会话分叉（fork）**。分叉出的两条线会同时改同一份工作区，而 SHE 的会话是钉在目录上的；真需要并行改文件时，工作副本给的是真隔离（独立目录、互不覆盖），比共享同一目录的分叉安全。不做共享工作区的分叉。
- **把历史压成摘要**。完整记录是错题本和轨迹回看（条目 12、23）的原料，压掉的恰好是「当时到底试过什么」。省上下文靠检索和轨迹，不靠丢原文。
- **产品级 token / 步数 / 调用次数配额**。配额会在长任务中途把它掐断，而重来一遍的代价通常比超支更大。这一条限制的是「无效」而不是「总量」：同样调用重复三次仍然会停。
- **显卡集群调度**。本 Agent 是无 IDE、完全依赖 API 的本地进程，没有可调度的加速卡。对应任务改写成模型路由（强度档 + 备用接口）。
- **数字孪生**。需要一套与真实系统持续同步的仿真设施，超出「本地 Agent + 工作区」的范围。对应任务改写成项目状态与工作区工具。

从「不做」里移出的一条：

- **屏幕操作没有接口的老系统 —— 已做。** `computer_click` / `computer_type` / `computer_key` / `computer_scroll`（`packages/sandbox/src/computer.ts`）负责动手，`screenshot` 负责看，合起来才是「能操作一个没有 API 的系统」。默认关闭：需要 `SHE_ALLOW_COMPUTER_USE=true`，这是独立于「允许所有命令」的第二道授权（前者管工作区内的文件，后者管你的鼠标键盘），且工具仍标 `isDangerous`，照走确认门。目前仅 Windows，非 Windows 会明确报「不可用」而不是假装成功。

## 必须项

### 1 身份、目标与边界 — 部分

要做到：开工前说清角色、任务范围、不能做的事；分清目标和字面指令；越界就停，不编结果；能力声明能被人看懂。

已有：技能档（开发 / 创作 / 通用 / 自定义）、系统提示、确认门、破坏性命令默认拒绝。

还要补：执行前边界自检；高风险或指令不完整时先停下来说明，而不是直接调工具。

### 2 多源输入理解 — 部分

要做到：文本、表格、文件、日志、代码、配置、接口结果放在同一轮里理解；抽出目标、约束、风险、交付格式；标出歧义、缺失和矛盾。

已有：`@file` / `@folder` / `@symbol`、拖入文件、导入 Cursor / Claude / Codex 对话、视觉描述、知识库入库。

还要补：一轮开始时把「事实 / 偏好 / 假设 / 缺什么」写成结构，而不是只靠模型自己记得。

### 3 上下文与状态追踪 — 部分

要做到：记住做完了什么、卡在哪、关键决定；中断后从原处继续；长期记忆和这一轮的临时内容分开。

已有：全量历史（不压缩）、计划跨会话、知识库、换聊天不停正在跑的一轮、旧会话读入时钉住所在项目。

还要补：一轮失败或人停掉之后，按计划把未完成步骤接着做，而不是只留一句「失败了」。批次 D 之后计划这一侧**已经准备好**了：`.she/plans.json` 里有完整状态、依赖和 `下一步:` 那一行，重启或换会话后读一次就知道从哪继续（`check:plan` 里就是丢掉 toolset 再建一个来验的）。缺的是**循环自己不会回来**：一轮失败/被中止后没有自动重入，要靠模型下次主动 `plan_list`。

### 4 任务拆解与规划 — 部分

要做到：拆成可执行步骤，写清依赖、工具、成功条件和失败时怎么办；无依赖的步骤并行；做的过程中可以改计划。

已有：`plan_create` / `plan_update` / `plan_list`，各模式提示里要求先立计划，计划在整个工作区可见。

**已做**（批次 D，`check:plan`）：步骤可以声明 `depends_on` 与 `on_failure`。前置没完成时**开始或标完成都会被拒绝**，拒绝信息点名是哪一步挡着（不是笼统的失败），所以「4/4 完成」不会再盖在没做过的前置上。`on_failure` 是计划自己的处置办法：`retry` 换个做法再来（并且**记次数**，「已试 3 次」是个决策点，不记次数的重试就是静默死循环）、`skip` **级联跳过**依赖它的步骤并写清是谁害的（否则那些步骤在等永远不会来的输入，计划就永远挂在那里）、`ask` 指明该问用户、`stop` 停在 `[!]` 并说需要用户决定。渲染出的计划以 **`下一步: s2 构建产物`** 收尾——「续做」读的是这一行而不是状态标记，它在重启后、在另一个会话里都已经算好了前置，而且和工具输出用的是同一份规则（`nextStepOf`），两者不可能互相矛盾。做完的计划又被加活会**重新打开**（否则 `active()` 跳过它，新步骤躺在没人读的文件里）；成环和指向不存在步骤的依赖被拒绝且**不落盘**。UI 的 `PlanPanel` 也把「下一步」、依赖、策略、试了几次显示出来，且「下一步」由服务端算好下发。

还要补：无依赖步骤并行**已做了只读的那一半**（批次 I，`check:budget`：同一轮里开头连续的只读调用按白名单并发、上限 4；互不依赖的写仍串行，因为还没有声明式的「谁碰哪些文件」边界）。失败后按依赖**重排**还只是拒绝越序 + 级联跳过，没有「重排剩余顺序」的主动规划能力。

### 5 推理、判断与决策 — 部分

要做到：分开已确认的事实和待验证的假设；信息不够时决定是再查还是说明不可靠；冲突时说明信谁；不编造接口、文件和执行结果。

已有：推理强度、思维链展示、引用知识库时带组和节点。

还要补：回答里固定区分事实、假设、来源；高风险决定再查一次。

### 6 工具调用与外接 API — 部分

要做到：按目标选工具；调用前查参数；调用后查返回是不是能用；超时、限流、空结果、部分成功有去路；敏感调用先拦住；工具挂了能换路。

已有：工具循环、MCP、插件、接口重试和备用地址、同样调用重复三次会停、确认票据不交给模型。

还要补：返回值统一校验；失败原因分类（参数、权限、没有数据、服务挂了）；无依赖的工具可以并行。

**已做**（`tool-result.ts` + `check:toolresult`）：返回值统一过一遍 `classifyToolResult`，分成 11 类——参数、权限、工具不可用、目标不存在、状态前提未满足、空结果、服务不可达、超时、限流、非零退出码、未识别。两处以前看不见的失败现在会说话：非零退出码以前被当成成功（`shell` 把 `exit code: 1` 当普通文本输出），以及「没有匹配」以前被当成数据（`grep`/`kb_query` 的空结果就是答案，不是错误）。每类都给一句「下一步怎么办」并贴在工具结果后面，模型看得到。确认门与补丁待应用是**状态**不是失败，单独排除。判定里还带一个 `retryable`（重试同样的调用有没有意义），它接线给了卡死检测：瞬时失败多给一次机会，见下一段。

**已做**（批次 I + `check:budget`）：无依赖的**只读**调用并行化（`read-batch.ts`）。只取开头连续的一段，遇到不在白名单里的名字、没见过的工具名、或任何写就停下走串行——赌错方向的代价不对称：错判「可以并行」会让读写交错，错判「不能」只花几毫秒。白名单是静态的（`fs_read`/`fs_list`/`grep`/`git_status`/`git_diff`/`git_log`/`kb_query`/`errorbook_lookup`/`memo_list`/`plan_list`/`schedule_list`/`schedule_window`/`reflection_check`），上限 `MAX_PARALLEL_READS = 4`。同轮相同的只读查询复用结果：身份是「工具名 + 规范化后的参数」（参数顺序不同算同一个），缓存只活一轮，任何非只读调用一跑就整轮作废——不是靠「这个工具大概率会写」的启发式，而是拒绝假设否则（避免读到写之前的旧内容却和正确答案长得一样），复用时给用户一行状态说明。卡死检测用上了 `retryable`：瞬时失败（超时/限流/服务不可达）比永久失败多给一次。

**待做**：步骤级的并行仍然只限于只读调用。计划图里两个互不依赖的**写**步骤（不同文件）目前还是串行——要做需要先有「谁碰哪些文件」的声明式边界，否则并行写会互相覆盖，而这类 bug 在真实工作区里是不可接受的。另外，同轮复用只看参数相等，还看不出「这两次查询的结果本来就一样」（例如 `fs_read` 同一文件的不同行段）。

### 7 数据获取、清洗与整合 — 部分

要做到：多来源对齐、去重、标出原始数据和推断；数据不够就说明结论不可靠；留下来源和查询条件。

已有：知识库归位（扫描、列出、放入）、组路径检索。

还要补：多份工具结果合并时的字段对齐和来源；不把局部结果说成全局。

### 8 记忆、知识沉淀与经验复用 — 部分

要做到：记下有效路径和失败路径；用户偏好和项目事实分开；过时知识能标失效；相似任务能检索到。

已有：知识库写入和检索、组名能命中、边必须两端都存在、因果边要有证据和可证伪条件；错题本（失败路径自动入库、下次查得到，见 `packages/agent-runtime/src/errorbook.ts` + `check:errorbook`）。

还要补：成功路径没有对应机制（只有失败路径入库）；过时知识标失效还没有；偏好不写进事实组（现在是靠不写，不是靠校验）。

### 9 执行控制、容错与恢复 — 部分

要做到：看得见进度；失败能重试、降级或跳过并写下原因；关键步骤失败回到安全状态；长任务有检查点；无效循环会停；失败报告写清位置、原因、试过什么、下一步。

已有：失败会收成可继续的对话、备用接口、补丁可撤销、人可以中断、流断了保留已收到的字、工作区外的路径和 `../` 会被拒绝。

还要补：按计划从中断处恢复；失败报告成为固定产物，而不是只在对话里说一句。

### 10 自我校验与质量 — 部分

要做到：做之前、做之中、做完后都检查；缺了、矛盾了、不能用，要标出来；发现错了自己改。

已有：提示要求改完用诊断或真的跑一遍；语言服务没有时退回语法检查；每次工具返回后都有一次轻量检查（`tool-result.ts` 分类 + 去路，接在 `agent.ts` 的每一步上，`check:toolresult` 保证没有漏网的失败文案）；同一个调用连续三次同样结果会停并把这条路径写进错题本。

还要补：交付前的完整性检查写进轨迹（批次 E、G）；矛盾检测（批次 H）。

### 11 安全、合规、权限与治理 — 部分

要做到：敏感操作显式授权；最小权限；输入防注入和越权；审计能追溯谁要求的、决定了什么、调了什么。

已有：沙箱、确认门、破坏性命令默认拒绝、插件不能顶掉内置工具、路径逃逸拒绝。

还要补：一条可检索的审计记录（请求、决定、工具、确认），而不只是聊天记录。**已做**（批次 F，`packages/server/src/audit.ts` + `check:audit`：`.she/audit.log` 一行一条 JSON、只追加（已有字节是原文前缀）、`seq` 跨重启与轮转严格递增、超限轮转并在丢弃时写下 `rotation` 记录、损坏行被计数并经 `GET /api/audit` 报出、长消息截断但保留原长；三处接线是 `/api/chat`（请求）、工具观察器（每次工具调用，含确认后执行的那些）、`/api/chat/confirm`（人工批准）。批准前先校验工单，伪造或过期的 `ticket_id` 得到 409 而不是一条「人工已批准」；接口只读，界面面板也明说只读。**「决定」这一类目前只有人工批准这一种**：模型自己的取舍（选这条计划而不是那条）还没有独立的记录落点。批次 H 的反思/漂移把漂移、反复过度自信、同一工具再失败、跑满迭代上限写成了**教训**（`errors/自省`，见第 23 条），但那是知识库里可检索的教训，不是审计时间线上的一条「决定」；要把「为什么选这条计划」也挂上时间线是另一件事。

### 12 可解释、可观测、可调试 — 部分

要做到：说得清为什么这样理解、为什么选这个计划和这个工具；轨迹能回放；错误分成系统、输入、工具、规划、数据。

已有：思维链、工具卡片、用量、任务板、会话条上的「进行中」。

还要补：一次运行的步骤轨迹能事后打开，而不是只在当时的气泡里。

### 13 人机协作 — 已有，仍要补超时策略

要做到：关键点让人确认；给人能选的选项而不是一堆日志；人改了之后接着做；人一直不回应就暂停，不自己做危险的事。

已有：确认、补丁应用/拒绝、`ask_user`、执行中补充消息、确认期间可以停止。

还要补：确认和提问超时后明确暂停，并记下「在等谁」。

### 14 多 Agent 协作 — 部分

要做到：判断该不该分出去；把必要上下文交给别人；并行、合并、处理冲突；记录谁做了哪一步；失败时指出是规划、工具、交接还是合并。

已有：工作群（名册、头像、并行做事和审查）、子会话可后台、一个人失败不拖垮整群。

还要补：子任务改文件时进独立工作副本；交接时带上目标和约束，不只丢一段提示。

### 15 输出与交付 — 部分

要做到：结论、证据、假设、风险、待确认分开；不装成完整；同一件事能出简版和详版。

已有：`report_write`、会话和群组导出。

**已做**（批次 E，`check:delivery`）：`report_write` 加了 `kind: "delivery"`，走五栏模板——结论 / 证据 / 假设 / 风险 / 待确认（这五栏正是互相容易矛盾的那五栏）。**证据是必填**：没有证据的结论是断言，而用户没看过那条命令。`status` 不是自称而是被检查的：`done` 在 `open` 非空时被拒，在**本会话**计划还有没做完（非 `done`/`dropped`）的步骤时被拒并点名那些步骤；同一件活改写成 `partial` 并把它们放进 `open` 就能交。作用域两个方向都重要：别的会话的计划既不拦这次交付，也不会被这次交付冒充——否则绕过检查最省事的办法就是把步骤标成 `done` 来解锁「done」这个词，正是这个检查要防的行为。产物里自动带上交付时点还没做完的计划步骤，读者不必自己去翻。`brief` 省略空小节；`full` 要求显式给出假设与风险（空数组是结论，缺字段是没想），空小节印「（无）」而不是消失——印了标题却没人填的文档看起来更完整，那正是要避免的。

**剩下的缺口**：简版 / 详版是**同一次调用里选一个**，还没有「一次任务同时产出两份（简版给结论、详版给依据）」。另外这几栏仍是模型自己写的——但「证据真的来自那次执行」现在**可以核对**了（批次 G，`corroborate`）：这轮跑过哪些工具、哪条内容在轨迹里出现过，都能查；点名了本会话没跑过的工具的证据会被直接拒掉。它**不**核对措辞是否逐字一致，也不声称未出现在轨迹里的事就没发生——那是留给读轨迹的人的判断。

### 16 成本与性能 — 部分（按决定不设配额）

要做到：不重复打同一个没用的调用；并发别把外部服务打满；说清这次为了快牺牲了什么。

已有：重复调用会停、流式、接口重试有次数。

**已做**（批次 I + `check:budget`）：相同只读查询在这一轮内复用结果；只读调用按白名单并发（上限 4）。

**已做，但默认关着**：预算开关（`budget.enabled`，三个轴 `maxToolRounds` / `maxToolCalls` 与 `maxSeconds` / `maxTokens`）。默认全 0 = 不设配额，与「不另加会截断任务的配额」这个决定一致；要设限的人自己打开，且检查点都在**还没干活**的位置（跑下一轮之前、一条消息里的工具动手之前、工具与工具之间）。到限不等于是失败：独立收尾、轨迹记 `budget`，文案说明是哪条轴、用了多少、说「继续」就能接着做，已经发出的调用补 `not_run` 让下一轮还能追加。

**待做**：并发数还是固定 4，不感知外部服务的实际承受能力（「并发别把外部服务打满」只做到了上限，没做到自适应）。

### 17 版本、配置与环境 — 部分

### 18 评测与持续优化 — 部分

### 23 自省 — 大部分

已有：思维链给人看；提示要求验证；错题进知识库（`errors/<tool>`，同一失败累计次数、跨会话可查，`errorbook_lookup` 只读）；开工前先查错题（`preflight_record` 把查到的历史写进分析）。

**已做**（批次 H，`check:reflection`）：

- **语义漂移检测**（`detectDrift`）是纯词法、确定的：拿最初的 `actual_goal` / `stated_intent` 与约束去比现在的动作和计划步骤。硬约束（显式禁止、「不要」这类措辞）越界才算漂移并设 `replan: true`，软约束只提醒——把偏好当成违规会让检查变得狼来了，然后被无视。报的是被碰到的**对象**而不是整句话，消息里能说出到底动了什么。这一块**故意不用模型**：能幻觉出违规的自省比没有更糟，而它必须在智能体最想替自己找补的那一轮里还值得被相信。
- **置信度镜像**（`ConfidenceMirror`，`.she/reflection/confidence.json`）拿预检时的**自评**对比本轮**实际**的工具成功率（`succeeded / attempted`）。滑窗让一段旧的坏运气不再一直给现在上色；结论只有 `overconfident` / `underconfident` / `calibrated`——要的是被告知偏哪边，不是拿到一个可以自我合理化的数字。两个输入都要求存在，任一缺失就不产生样本：没有自评不进样本，一轮没调工具不算满分（否则「声称很有把握然后什么都不做」会被记成校准良好）。`succeeded` 超过 `attempted`（调用方数错）会被夹住，否则是**输入**的 bug 被报成**欠自信**。结论以一小段注入系统提示词，前缀保持逐字节不变，不会把它本来要保护的提示词缓存冲掉。
- **反思入错题本**（`ErrorBook.recordReflection`）：漂移、反复过度自信、同一个工具再次失败、跑满迭代上限都会经 KB 原语写进 `errors/自省`，以主题当签名——同一主题复发是**计数 +1** 而不是再堆一条近似重复。`errorbook_lookup` 相应放宽到能直接匹配反思主题，查不回来的教训只是日记。
- **独立批评者**（`critic.ts`）：拿回答里的说法去对已落盘的运行轨迹。说「工具跑成功了」而它最后一次是失败 → `contradicted`（判 `fail`）；点名了从没跑过的工具、或产物不存在 → `unbacked`（`concerns`）；泛泛而谈 → `unverifiable`，不进结论。它是一条独立角色（hue 350，review 相位），在讨论群里插在 work 与 review 之间跑，所以检查不是产出那一步自己给自己盖章。引用只认「长得像产物」的 ASCII token——早先的版本把中文四字词当成引文，结果把正常中文句子判成无据。`GET /api/reflection` 提供镜像读数，**新进程**也能从盘上读到历史；`POST /api/reflection/confidence/reset` 在审计里留一条 `config`，因为清掉别人的校准历史是一件值得能追溯到日期的事。

还要补：危险写入后的检查卡口（写坏之后的最后一道拦截）。不做运行中改自己的程序。

还要补：真正要的结果更依赖模型判断，目前只是提示词要求，没有可验证的机制。`.she/preflight/` 的记录还没有 UI。**下一轮会被自动读回**：每轮开轨迹时会把该会话最近一份预检记录作为 `preflight` 事件写进去（批次 G），所以读者能在轨迹里看到这一轮带着哪份分析开工；但要读全量预检，还得去看 `.she/preflight/`。
