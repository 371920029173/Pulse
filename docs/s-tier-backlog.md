# SHE 能力任务清单（已确认）

对照桌面 `a.txt`。必须项和加分项都在这份清单里。每一大条写三件事：要做到什么、现有实现对得上哪、还要补什么。

状态：已有 / 部分 / 未做。

不做的只有这几件，其余加分项都改写成 SHE 做得到的任务，不整段删掉。每条都写清理由，避免下次再拿出来重新讨论一遍：

- **会话分叉（fork）**。分叉出的两条线会同时改同一份工作区，而 SHE 的会话是钉在目录上的；真需要并行改文件时，工作副本给的是真隔离（独立目录、互不覆盖），比共享同一目录的分叉安全。不做共享工作区的分叉。
- **把历史压成摘要**。完整记录是错题本和轨迹回看（条目 12、23）的原料，压掉的恰好是「当时到底试过什么」。省上下文靠检索和轨迹，不靠丢原文。
- **产品级 token / 步数 / 调用次数配额**。配额会在长任务中途把它掐断，而重来一遍的代价通常比超支更大。这一条限制的是「无效」而不是「总量」：同样调用重复三次仍然会停。
- **显卡集群调度**。本 Agent 是无 IDE、完全依赖 API 的本地进程，没有可调度的加速卡。对应任务改写成模型路由（强度档 + 备用接口）。
- **数字孪生**。需要一套与真实系统持续同步的仿真设施，超出「本地 Agent + 工作区」的范围。对应任务改写成项目状态与工作区工具。

从「不做」里移出的一条：

- **屏幕操作没有接口的老系统 —— 已做。** `computer_click` / `computer_type` / `computer_key` / `computer_scroll`（`packages/sandbox/src/computer.ts`）负责动手，`screenshot` 负责看，合起来才是「能操作一个没有 API 的系统」。默认关闭：需要 `SHE_ALLOW_COMPUTER_USE=true`，这是独立于「允许所有命令」的第二道授权（前者管工作区内的文件，后者管你的鼠标键盘），且工具仍标 `isDangerous`，照走确认门。目前仅 Windows，非 Windows 会明确报「不可用」而不是假装成功。

## 必须项

### 1 身份、目标与边界 — 部分

要做到：开工前说清角色、任务范围、不能做的事；分清目标和字面指令；越界就停，不编结果；能力声明能被人看懂。

已有：技能档（开发 / 创作 / 通用 / 自定义）、系统提示、确认门、破坏性命令默认拒绝。

还要补：执行前边界自检；高风险或指令不完整时先停下来说明，而不是直接调工具。

### 2 多源输入理解 — 部分

要做到：文本、表格、文件、日志、代码、配置、接口结果放在同一轮里理解；抽出目标、约束、风险、交付格式；标出歧义、缺失和矛盾。

已有：`@file` / `@folder` / `@symbol`、拖入文件、导入 Cursor / Claude / Codex 对话、视觉描述、知识库入库。

还要补：一轮开始时把「事实 / 偏好 / 假设 / 缺什么」写成结构，而不是只靠模型自己记得。

### 3 上下文与状态追踪 — 部分

要做到：记住做完了什么、卡在哪、关键决定；中断后从原处继续；长期记忆和这一轮的临时内容分开。

已有：全量历史（不压缩）、计划跨会话、知识库、换聊天不停正在跑的一轮、旧会话读入时钉住所在项目。

还要补：一轮失败或人停掉之后，按计划把未完成步骤接着做，而不是只留一句「失败了」。批次 D 之后计划这一侧**已经准备好**了：`.she/plans.json` 里有完整状态、依赖和 `下一步:` 那一行，重启或换会话后读一次就知道从哪继续（`check:plan` 里就是丢掉 toolset 再建一个来验的）。缺的是**循环自己不会回来**：一轮失败/被中止后没有自动重入，要靠模型下次主动 `plan_list`。

### 4 任务拆解与规划 — 部分

要做到：拆成可执行步骤，写清依赖、工具、成功条件和失败时怎么办；无依赖的步骤并行；做的过程中可以改计划。

已有：`plan_create` / `plan_update` / `plan_list`，各模式提示里要求先立计划，计划在整个工作区可见。

**已做**（批次 D，`check:plan`）：步骤可以声明 `depends_on` 与 `on_failure`。前置没完成时**开始或标完成都会被拒绝**，拒绝信息点名是哪一步挡着（不是笼统的失败），所以「4/4 完成」不会再盖在没做过的前置上。`on_failure` 是计划自己的处置办法：`retry` 换个做法再来（并且**记次数**，「已试 3 次」是个决策点，不记次数的重试就是静默死循环）、`skip` **级联跳过**依赖它的步骤并写清是谁害的（否则那些步骤在等永远不会来的输入，计划就永远挂在那里）、`ask` 指明该问用户、`stop` 停在 `[!]` 并说需要用户决定。渲染出的计划以 **`下一步: s2 构建产物`** 收尾——「续做」读的是这一行而不是状态标记，它在重启后、在另一个会话里都已经算好了前置，而且和工具输出用的是同一份规则（`nextStepOf`），两者不可能互相矛盾。做完的计划又被加活会**重新打开**（否则 `active()` 跳过它，新步骤躺在没人读的文件里）；成环和指向不存在步骤的依赖被拒绝且**不落盘**。UI 的 `PlanPanel` 也把「下一步」、依赖、策略、试了几次显示出来，且「下一步」由服务端算好下发。

还要补：无依赖步骤并行（批次 I）。失败后按依赖**重排**还只是拒绝越序 + 级联跳过，没有「重排剩余顺序」的主动规划能力。

### 5 推理、判断与决策 — 部分

要做到：分开已确认的事实和待验证的假设；信息不够时决定是再查还是说明不可靠；冲突时说明信谁；不编造接口、文件和执行结果。

已有：推理强度、思维链展示、引用知识库时带组和节点。

还要补：回答里固定区分事实、假设、来源；高风险决定再查一次。

### 6 工具调用与外接 API — 部分

要做到：按目标选工具；调用前查参数；调用后查返回是不是能用；超时、限流、空结果、部分成功有去路；敏感调用先拦住；工具挂了能换路。

已有：工具循环、MCP、插件、接口重试和备用地址、同样调用重复三次会停、确认票据不交给模型。

还要补：返回值统一校验；失败原因分类（参数、权限、没有数据、服务挂了）；无依赖的工具可以并行。

**已做**（`tool-result.ts` + `check:toolresult`）：返回值统一过一遍 `classifyToolResult`，分成 11 类——参数、权限、工具不可用、目标不存在、状态前提未满足、空结果、服务不可达、超时、限流、非零退出码、未识别。两处以前看不见的失败现在会说话：非零退出码以前被当成成功（`shell` 把 `exit code: 1` 当普通文本输出），以及「没有匹配」以前被当成数据（`grep`/`kb_query` 的空结果就是答案，不是错误）。每类都给一句「下一步怎么办」并贴在工具结果后面，模型看得到。确认门与补丁待应用是**状态**不是失败，单独排除。判定里还带一个 `retryable`（重试同样的调用有没有意义），目前只有测试在读它——接线给卡死检测是下面「待做」的一部分。

**待做**（批次 I）：无依赖步骤并行、同轮只读查询复用。**待做**：让卡死检测用上 `retryable`——现在「同样的调用、同样的结果」一律按卡死处理，但超时/限流这类瞬时失败重试本来就是对的，不该被当成模型在原地打转。

### 7 数据获取、清洗与整合 — 部分

要做到：多来源对齐、去重、标出原始数据和推断；数据不够就说明结论不可靠；留下来源和查询条件。

### 8 记忆、知识沉淀与经验复用 — 部分

### 9 执行控制、容错与恢复 — 部分

### 10 自我校验与质量 — 部分

已有（原来记在「还要补」里，其实已经成立）：

### 24 意图分析 — 部分

要做到：分开字面诉求、没说出口的约束、真正要的结果；缺了就问；硬条件和软条件分开；高风险先确认。

已有：`preflight_record`（开工前调用一次）把四样东西分开写下来：字面诉求、推断出的约束、实际目标、还要问什么，并落盘到 `.she/preflight/`，一条一个文件。

确定性的一半不调模型、免费、进门禁：拿请求去对工作区和**这个会话实际拿到的工具表**，逐个检查 `@file:` / `@folder:` / `@symbol:` 引用、时间表达、破坏性字眼，标成 ✓ / ✗ / !。所以能抓到提示词抓不到的东西——用户点名但不存在的文件、沙箱外路径、「明天提醒我」而这个会话没有排程工具、`@symbol:` 但没有语言服务器。声称的置信度会被**压**到检查结果允许的上限，并且明确说明压过，而不是悄悄改。

约束分硬/软：工作区边界、不可逆操作是硬条件；旧计划、技能档是软条件（旧计划不再被当成续做指令）。

还要补：真正要的结果更依赖模型判断，目前只是提示词要求，没有可验证的机制。.she/preflight/ 的记录还没有 UI，也不会被下一轮自动读回（批次 G 的 run trace 会接上）。

### 长程任务自主规划 — 部分

要做到：模糊目标拆成有依赖的步骤；跨会话维持；中断后从检查点继续；定时和后台任务；多条路里选一条，而不是一条死路走到底。
